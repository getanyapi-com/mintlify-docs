---
title: "Let your agent onboard itself"
description: "Point an AI agent at AnyAPI and it provisions its own free trial key, reads the catalog, and starts calling APIs. You just prompt it - no signup, no email, no copied credentials."
---

From one prompt, the agent installs the AnyAPI skills, mints its own **free trial key**,
and makes its first call. You create no account and hand over no credentials. When the
trial budget runs out, one human approval keeps it going.

<Info>
  This page is for an **autonomous agent that calls AnyAPI at runtime**. If a coding agent
  is **integrating AnyAPI into an app you'll ship**, create a
  [dashboard key](https://getanyapi.com/dashboard/keys) on your funded account and see
  [Agent skills](/agent-skills). Trial keys have a small budget and expire in 7 days, so
  they do not belong in shipped code.
</Info>

## The one thing you do

Prompt your agent:

```text
You have access to AnyAPI, a pay-per-call marketplace for scraping and data APIs.
Read https://getanyapi.com/agent-onboarding/SKILL.md, onboard yourself, and make one
real API call. Report what you did.
```

<Note>
  To have the agent spend from your funded account instead, hand it an
  [API key](https://getanyapi.com/dashboard/keys) and skip the trial.
</Note>

## What the agent does on its own

<Steps>
  <Step title="Installs the CLI (if it has a shell)">
    An agent with a shell runs one command that installs the skills, mints the trial key,
    and writes local credentials:

    ```bash
    npx -y anyapi-cli@latest init
    ```

    `anyapi init` also offers MCP registration and saves the key to
    `~/.anyapi/config.json`. After init, the agent calls the `anyapi` binary directly.
  </Step>
  <Step title="Mints its own free trial key">
    Without a shell (a hosted chat or no-code runtime), the agent posts to the public signup
    endpoint:

    ```bash
    curl -X POST https://api.getanyapi.com/agent/signup \
      -H "Content-Type: application/json" \
      -d '{ "label": "my-agent" }'
    ```

    The body is optional; `label` tags the key. The response returns the key once, plus
    the upgrade details:

    ```json
    {
      "secret": "aa_live_…",
      "keyId": "42",
      "capUsd": 0.05,
      "expiresAt": "2026-07-17T00:00:00Z",
      "clientId": "…",
      "upgrade": {
        "authorizationServer": "https://api.getanyapi.com",
        "scope": "run balance:read"
      },
      "notice": "This is a free AnyAPI trial key: about $0.05 of requests, it self-expires in 7 days, and no account was created. When it runs out, your human can connect a wallet to keep it going."
    }
    ```

    The agent stores `secret` as `ANYAPI_API_KEY` and relays `notice` to you verbatim.
  </Step>
  <Step title="Starts working immediately">
    The agent lists APIs, reads schemas, checks its USD balance, and runs calls over
    [MCP](/mcp-server), the CLI, or REST.
  </Step>
</Steps>

## What it costs you to start

Nothing. A trial key carries about **$0.05 of requests** (`capUsd`), **creates no
account**, and **self-expires in 7 days** if never upgraded.

<Warning>
  When the trial budget is spent, calls return **HTTP 402** with error code
  `trial_cap_reached` and an `upgrade` object in the body. Approve continued spend below.
</Warning>

## Upgrade past the trial

Continuing takes one human approval through OAuth 2.1. You approve a spend limit, and the
agent keeps working on the same session without a new key.

Approve from your personal account. A trial can't be continued on a [Team](/teams).

<Tabs>
  <Tab title="With the CLI (recommended)">
    The agent runs:

    ```bash
    anyapi connect
    ```

    This requires `anyapi-cli >= 0.3.0`. It starts an OAuth flow with a localhost callback
    and prints **one consent URL** for the human. At
    [getanyapi.com/dashboard/authorize](https://getanyapi.com/dashboard/authorize) they sign
    in or sign up, see a **receipt of what the agent did on the trial**, set a spend limit,
    and approve. The agent then holds an OAuth access token.
  </Tab>
  <Tab title="Raw REST or MCP (no shell)">
    The `402 trial_cap_reached` body carries the `upgrade` coordinates
    (`authorizationServer` and `scope`). The agent relays the link so you can approve
    continued spend at
    [getanyapi.com/dashboard/authorize](https://getanyapi.com/dashboard/authorize).
  </Tab>
  <Tab title="Dashboard key (secondary)">
    Create a **non-expiring** key at
    [getanyapi.com/dashboard/keys](https://getanyapi.com/dashboard/keys) and give it to the
    agent as `ANYAPI_API_KEY`. New accounts start with about **100 free requests**. Use this
    path on a CLI too old for `anyapi connect`.
  </Tab>
</Tabs>

## Sign up your person over plain HTTP

An agent with only HTTP that can message you can connect it to your own AnyAPI account
instead of a trial key. It follows the `service_auth` flow in
[auth.md](https://getanyapi.com/auth.md), which has the full request and response detail.

<Steps>
  <Step title="Registers with your email">
    The agent asks for your email and sends it as `login_hint`:

    ```bash
    curl -X POST https://api.getanyapi.com/agent/identity \
      -H "Content-Type: application/json" \
      -d '{ "type": "service_auth", "login_hint": "you@example.com", "client_name": "My agent" }'
    ```

    The response carries a `claim_token` the agent keeps private, and a `claim` block with
    a `user_code` and a `verification_uri`.
  </Step>
  <Step title="Hands you a link and a code">
    You open [getanyapi.com/dashboard/authorize](https://getanyapi.com/dashboard/authorize),
    sign in or sign up with that email, and type the code. Only an account that holds the
    email as a verified address can approve.
  </Step>
  <Step title="Polls for its token">
    The agent polls `https://api.getanyapi.com/oauth/token` with
    `grant_type=urn:workos:agent-auth:grant-type:claim` and its `claim_token`. Once you
    approve, it gets an `aa_at_` access token, valid for one hour, and an `aa_ia_`
    `identity_assertion`.
  </Step>
  <Step title="Refreshes on its own">
    When the access token expires, the agent exchanges the `identity_assertion` with
    `grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer` for a new one. You don't
    approve again.
  </Step>
</Steps>

An access token works on one interface. By default that is the REST API. For the
[MCP server](/mcp-server), the agent adds `resource=https://api.getanyapi.com/mcp` to the
token request.

If the code expires before you approve, the agent gets a fresh one from
`POST https://api.getanyapi.com/agent/identity/claim` with its `claim_token` and your email.
A registration stays open for 24 hours.

<Tip>
  Connect the [MCP server](/mcp-server) for live tools, or use the [CLI](/cli) to keep tool
  schemas out of the agent's context window.
</Tip>
