Your endpoint serves one catalog API. AnyAPI sends it signed POST requests in that API's
input format, and your endpoint answers in its output format.

<Info>
  [APIs open to sellers](/sell/apis/index) lists the APIs you can register, with each one's
  request, response, and published price. To sell any other API, email
  [support@getanyapi.com](mailto:support@getanyapi.com).
</Info>

## The request you receive

AnyAPI POSTs the API's input as JSON to your registered path (default `/run`):

```http
POST /run HTTP/1.1
Host: scraper.example.com
Content-Type: application/json
X-AnyAPI-Operator: op_9f2kd83m
X-AnyAPI-Timestamp: 1767312000
X-AnyAPI-Nonce: 3f9c2ab84d1e07c6b52a91f0d4e8a713
X-AnyAPI-Signature: 8d1f0a5b9c3e...

{"query": "best pizza brooklyn", "limit": 10}
```

The body always matches the API's **input JSON Schema**. Read it and the output schema
from the catalog:

```bash
curl https://api.getanyapi.com/v1/apis/{sku} \
  -H "Authorization: Bearer aa_live_..."
```

The response includes `inputSchema` and `outputSchema`, which the compatibility checks and
the live trial judge against. The register dialog in the
[dashboard](https://getanyapi.com/dashboard/sell/endpoints) shows them too.

Redirects are never followed, so answer directly at the registered URL.

## Verifying the signature (required)

Every request carries four headers:

| Header | Value |
| --- | --- |
| `X-AnyAPI-Operator` | your operator id |
| `X-AnyAPI-Timestamp` | unix seconds |
| `X-AnyAPI-Nonce` | random 128-bit hex, unique per request |
| `X-AnyAPI-Signature` | HMAC-SHA256, lowercase hex |

Recompute the signature over this dot-joined string:

```text
<timestamp>.<nonce>.<method>.<path>.<sha256hex(body)>
```

`method` is `POST`, `path` is your registered path, and `sha256hex(body)` is the
lowercase-hex SHA-256 of the raw body bytes. Then:

1. HMAC-SHA256 the string with the signing secret you got at registration.
2. Compare it with the header in constant time.
3. Reject timestamps older than about 5 minutes.
4. Remember nonces for that window to block replays.

Reject failures with 401 and never process an unverified body.

<CodeGroup>

```typescript verify.ts
import { createHash, createHmac, timingSafeEqual } from 'node:crypto';

const FRESH_SECONDS = 300;
const seenNonces = new Map<string, number>(); // nonce -> expiry (use Redis in production)

export function verify(
  secret: string,
  headers: Record<string, string>,
  method: string,
  path: string,
  rawBody: Buffer,
): boolean {
  const ts = headers['x-anyapi-timestamp'];
  const nonce = headers['x-anyapi-nonce'];
  const sig = headers['x-anyapi-signature'];
  if (!ts || !nonce || !sig) return false;

  const age = Math.abs(Date.now() / 1000 - Number(ts));
  if (!Number.isFinite(age) || age > FRESH_SECONDS) return false;

  const now = Date.now() / 1000;
  for (const [n, exp] of seenNonces) if (exp < now) seenNonces.delete(n);
  if (seenNonces.has(nonce)) return false;
  seenNonces.set(nonce, now + FRESH_SECONDS);

  const bodyHash = createHash('sha256').update(rawBody).digest('hex');
  const canonical = `${ts}.${nonce}.${method}.${path}.${bodyHash}`;
  const expected = createHmac('sha256', secret).update(canonical).digest('hex');

  const a = Buffer.from(sig, 'utf8');
  const b = Buffer.from(expected, 'utf8');
  return a.length === b.length && timingSafeEqual(a, b);
}
```

```python verify.py
import hashlib
import hmac
import time

FRESH_SECONDS = 300
seen_nonces: dict[str, float] = {}  # nonce -> expiry (use Redis in production)


def verify(secret: str, headers: dict, method: str, path: str, raw_body: bytes) -> bool:
    ts = headers.get("x-anyapi-timestamp", "")
    nonce = headers.get("x-anyapi-nonce", "")
    sig = headers.get("x-anyapi-signature", "")
    if not ts or not nonce or not sig:
        return False

    try:
        if abs(time.time() - int(ts)) > FRESH_SECONDS:
            return False
    except ValueError:
        return False

    now = time.time()
    for n in [n for n, exp in seen_nonces.items() if exp < now]:
        del seen_nonces[n]
    if nonce in seen_nonces:
        return False
    seen_nonces[nonce] = now + FRESH_SECONDS

    body_hash = hashlib.sha256(raw_body).hexdigest()
    canonical = f"{ts}.{nonce}.{method}.{path}.{body_hash}"
    expected = hmac.new(secret.encode(), canonical.encode(), hashlib.sha256).hexdigest()
    return hmac.compare_digest(sig, expected)
```

```go verify.go
package main

import (
	"crypto/hmac"
	"crypto/sha256"
	"crypto/subtle"
	"encoding/hex"
	"math"
	"net/http"
	"strconv"
	"sync"
	"time"
)

const freshSeconds = 300

var (
	nonceMu sync.Mutex
	nonces  = map[string]time.Time{} // nonce -> expiry (use Redis in production)
)

func verify(secret string, r *http.Request, path string, rawBody []byte) bool {
	ts := r.Header.Get("X-AnyAPI-Timestamp")
	nonce := r.Header.Get("X-AnyAPI-Nonce")
	sig := r.Header.Get("X-AnyAPI-Signature")
	if ts == "" || nonce == "" || sig == "" {
		return false
	}

	sec, err := strconv.ParseInt(ts, 10, 64)
	if err != nil || math.Abs(time.Since(time.Unix(sec, 0)).Seconds()) > freshSeconds {
		return false
	}

	nonceMu.Lock()
	now := time.Now()
	for n, exp := range nonces {
		if exp.Before(now) {
			delete(nonces, n)
		}
	}
	_, replay := nonces[nonce]
	nonces[nonce] = now.Add(freshSeconds * time.Second)
	nonceMu.Unlock()
	if replay {
		return false
	}

	bodyHash := sha256.Sum256(rawBody)
	canonical := ts + "." + nonce + "." + r.Method + "." + path + "." + hex.EncodeToString(bodyHash[:])
	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write([]byte(canonical))
	expected := hex.EncodeToString(mac.Sum(nil))
	return subtle.ConstantTimeCompare([]byte(sig), []byte(expected)) == 1
}
```

## The response you must return

Reply `2xx` with JSON that validates against the API's output schema, in this envelope:

```json
{
  "found": true,
  "data": { ... }
}
```

- **Extra fields are kept; missing declared fields fail.** Anything beyond the schema is
  passed to the customer, but every declared field must be present.
- **No result is not an error.** When the entity does not exist, return the schema's
  `found: false` shape with a 2xx. That is a valid, billable answer.
- A non-2xx status, output that does not validate, or a timeout is a failed attempt. The
  request fails over to another provider, you do not earn it, and repeated failures pause
  the endpoint.

## What you're paid for

Every answer your endpoint gives is either charged to the customer, and you are paid 80%
of what they paid, or free to the customer and unpaid.

| Your answer | Customer | You | Next source tried |
| --- | --- | --- | --- |
| A real result | Charged | Paid 80% | No |
| `found: false` because the thing does not exist | Charged | Paid 80% | No |
| `found: false` because the account is suspended, private, or unavailable | Charged | Paid 80% | No |
| A search with zero results | Charged | Paid 80% | No |
| A bot wall or block page | Free | Unpaid | Yes |
| `found: true` with every required field empty | Free | Unpaid | Yes |
| An error (any non-2xx status) | Free | Unpaid | Yes |
| A timeout | Free | Unpaid | Yes |
| A rate limit (`429`) | Free | Unpaid | Yes |
| A malformed reply (not JSON, or not matching the schema) | Free | Unpaid | Yes |

If the site blocked you, rate limited you, or anything else went wrong, answer with a
non-2xx status (`429` for a rate limit). Never answer `found: false` or an empty result
for a call you could not make. A `found: false` may only carry a `reason` the API's
output schema lists.

## Verifying answers

AnyAPI may verify any answer your endpoint gives, at any time and at its own cost, against
independent sources.

- **An answer found false** is unpaid, and what it earned is taken back from your available
  balance. It counts as a failed request when AnyAPI shares requests among sellers. You get
  an email naming the request, the API, and what it cost.
- **Repeated false answers** can pause your endpoint or end your participation as a seller,
  at AnyAPI's discretion. A paused endpoint gets no requests; reply to the email you
  receive to talk about turning it back on.

## Budgets

| Budget | Limit |
| --- | --- |
| Response time | The API's time limit, set by AnyAPI and shown on the endpoint's page |
| Concurrent requests | Your declared capacity, 4 unless you set it |
| Response body | 8 MB |
| Transport | HTTPS on port 443, public host, no embedded credentials |

## How requests reach your endpoint

AnyAPI sends each request to the cheapest source on the API first, whoever runs it. Your
endpoint goes ahead of one of AnyAPI's own sources only when your price is lower; at the
same price, AnyAPI's goes first. Your endpoint gets at most its **capacity** in requests at
once; further requests go to the next cheapest source until one of yours finishes.

- **Capacity** is how many requests your endpoint takes at once. Declare it as `capacity`
  when you register with `POST /v1/operator/endpoints`; it defaults to 4. Change it from
  the endpoint's page in the [dashboard](https://getanyapi.com/dashboard/sell/endpoints) or
  with `POST /v1/operator/endpoints/{id}/capacity` and a body of `{"capacity": 8}`.
- **429 pauses your endpoint.** Answer `429` when you are overloaded. AnyAPI stops
  sending you requests until your `Retry-After` has passed, honored as given in seconds
  or as an HTTP date. Without a usable `Retry-After`, the pause lasts 60 seconds.
  Requests during the pause go to other endpoints.
- **The time limit is set per API.** AnyAPI sets how long it waits for any seller's
  endpoint on each API. The endpoint's page shows it, and so does `timeLimitSeconds` in
  `GET /v1/operator/endpoints/{id}`. A response after the limit counts as timed out: the
  buyer is not charged and you are not paid for it.
- **Ahead only while you finish as often.** Your endpoint stays ahead of one of AnyAPI's
  sources only while the share of its requests it finishes is at least that source's;
  otherwise it is asked right after it.
- **Endpoints at the same price share the requests.** Each request picks among them at
  random, weighted by how many paid requests each completed for the time its requests took
  over the last 30 days. A new endpoint with no traffic yet starts at the average of the
  endpoints at its price.

## What the compatibility checks test

When you run the checks from the dashboard or
`POST /v1/operator/endpoints/{id}/conformance`, AnyAPI sends the API's schema examples to
your endpoint as signed requests and verifies, per request:

1. HTTP 2xx
2. Output validates against the output schema
3. `found: true` for the example inputs
4. Answer within the API's time limit, the same limit live traffic runs under
5. Body under the 8 MB cap

Every check must pass to enter the live trial, and a pass starts it. A failed run
returns a per-check report, and you can rerun without limit.

During the live trial, mirrored requests also carry `X-AnyAPI-Trial: 1`, so you can tell
trial traffic from paid traffic in your logs.

## How the live trial works

An endpoint in the trial receives up to 500 mirrored real customer requests, paced evenly
across 7 days from its first request. Trial traffic is neither billed nor paid.

Each trial response is compared with what the customer was served:

- Agreeing on an empty list, or agreeing on `found: false`, counts as a pass.
- A non-2xx, a timeout, or output that does not validate against the schema counts as a
  failure.

Graduation needs at least 95% of compared requests passing, over at least 200 compared
requests spanning at least 7 days, with no fabricated or injected content.

A fix shipped part-way through the trial is measured by the remaining paced requests,
so a bad first day is not permanent.
