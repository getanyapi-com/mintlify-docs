Search TikTok's top results for a keyword (caption, views, likes, comments, shares) with cursor pagination.

This page is the seller-facing summary of one catalog API, `tiktok.search_top`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$1.20 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `cursor` | string | no | Pagination cursor from a previous response. |
| `publishTime` | string | no | Time-frame filter: yesterday, this-week, this-month, last-3-months, last-6-months, all-time. |
| `query` | string | yes | Keyword to search for (e.g. "funny"). |
| `region` | string | no | 2-letter country code for the proxy location (e.g. US, GB, FR). |
| `sortBy` | string | no | Sort order: relevance, most-liked, date-posted. |

## Fields that must never come back empty

- `author`
- `caption`
- `createdUtc`
- `id`
- `items`
- `url`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `items` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
