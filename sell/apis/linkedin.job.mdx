Fetch one LinkedIn job posting by URL: title, full description, location, salary when disclosed, applicant count, employment and workplace type, seniority, benefits, industries, apply links, posting and expiry dates, the hiring team, the applicant tracking system behind it, and the hiring company with its size, follower count, website and description.

This page is the seller-facing summary of one catalog API, `linkedin.job`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$1.50 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `url` | string | yes | Full LinkedIn job posting URL, e.g. https://www.linkedin.com/jobs/view/4431721875/. |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes | The job posting record, or null when not found. |
| `data.applicantTrackingSystem` | string | no | Applicant tracking system behind the posting (e.g. Workday, Lever, Greenhouse), when LinkedIn reports one. |
| `data.applicants` | integer | no | Number of applicants reported by LinkedIn. |
| `data.applyUrl` | string | no | External company apply URL when the job applies off-site. |
| `data.benefits` | array | no | Listed benefits. |
| `data.city` | string | no | City of the job location. |
| `data.company` | object | no | Hiring company details. |
| `data.company.description` | string | no | Company About text. |
| `data.company.employeeCount` | integer | no | Number of employees LinkedIn reports for the company. |
| `data.company.followerCount` | integer | no | Number of followers of the company page. |
| `data.company.id` | string | no | LinkedIn's numeric company id, as a string. |
| `data.company.linkedinUrl` | string | no | Canonical LinkedIn company URL. |
| `data.company.logo` | string | no | Company logo image URL. |
| `data.company.name` | string | no | Company name. |
| `data.company.universalName` | string | no | Company LinkedIn universal (vanity) name. |
| `data.company.website` | string | no | Company website. |
| `data.country` | string | no | Country of the job location. |
| `data.countryCode` | string | no | Two-letter country code of the job location. |
| `data.createdUtc` | number | no | UTC epoch timestamp in seconds (Unix time) the job was posted. Multiply by 1000 for a JS Date in milliseconds. |
| `data.descriptionText` | string | no | Full job description as plain text. |
| `data.easyApplyUrl` | string | no | LinkedIn Easy Apply URL when available. |
| `data.employmentType` | string | no | Employment type (e.g. full_time, contract, part_time). |
| `data.experienceLevel` | string | no | Seniority / experience level (e.g. Mid-Senior level, Entry level). |
| `data.expireUtc` | number | no | UTC epoch timestamp in seconds (Unix time) the posting expires. Multiply by 1000 for a JS Date in milliseconds. |
| `data.hiringTeam` | array | no | LinkedIn members named on the posting as the hiring contacts. |
| `data.hiringTeam[].linkedinUrl` | string | no | Canonical LinkedIn profile URL. |
| `data.hiringTeam[].name` | string | no | Member name. |
| `data.hiringTeam[].position` | string | no | Member headline or job title. |
| `data.id` | string | no | LinkedIn job posting id. |
| `data.industries` | array | no | Industries associated with the role. |
| `data.jobState` | string | no | Posting state reported by LinkedIn (e.g. LISTED, CLOSED). |
| `data.location` | string | no | Job location (city, region, or country). |
| `data.remote` | boolean | no | Whether LinkedIn flags the role as remote-allowed. |
| `data.salary` | object | no | Salary range when disclosed by the poster. |
| `data.salary.max` | number | no | Maximum salary. |
| `data.salary.min` | number | no | Minimum salary. |
| `data.salary.text` | string | no | Salary as displayed (e.g. '300,000 - 330,000 USD'). |
| `data.state` | string | no | State or region of the job location. |
| `data.title` | string | yes | Job title. |
| `data.url` | string | yes | Canonical LinkedIn job posting URL. |
| `data.views` | integer | no | Number of views LinkedIn reports for the posting. |
| `data.workplaceType` | string | no | Workplace type (e.g. remote, on_site, hybrid). |
| `found` | boolean | yes | Whether the job posting was found. |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `applicants`
- `descriptionText`
- `name`
- `title`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `benefits` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.

## Example request

```json
{
  "url": "https://www.linkedin.com/jobs/view/4431721875/"
}
```

The registration tests send this example to your endpoint, with the API's other test inputs. After that, the real-request check sends your endpoint real past customer inputs, and an AI reviewer compares each answer with AnyAPI's own answer to the same input.
