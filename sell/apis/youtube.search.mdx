Search YouTube and get matching videos (title, channel, views, length, publish time) as normalized JSON.

This page is the seller-facing summary of one catalog API, `youtube.search`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$0.50 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `cursor` | string | no | Continuation token from a previous response for pagination. |
| `query` | string | yes | The YouTube search query. |
| `requireCursor` | boolean | no | Deprecated; send `requireFields: ["nextCursor"]` instead, which does exactly the same thing. Set true if you intend to page through results, so the request is only served by a source that can return a nextCursor. Omit it and routing is unchanged, with the cheapest source serving. This can raise your price: when the cheapest source cannot page, a source that can serves, and you are quoted and charged its price. It stays accepted so callers that already send it keep working. |
| `requireFields` | array | no | Optional; omit it and routing is unchanged, with the cheapest source serving. Name the output fields this request must be able to return, for example `nextCursor`, and it is served only by a source that returns every one of them. Fields you do not name are still returned whenever the serving source has them. This can raise your price: when the cheapest source cannot return a named field, a dearer source serves, and you are quoted and charged its price. A named field can still be absent on a result that genuinely lacks it. Naming a combination that no single source returns together is refused as invalid input, with no charge. On a paginated walk it applies to the first page only; later pages stay with the source that page chose, at the price it was quoted. |
| `sortBy` | string | no | Sort order: "relevance" (default) or "popular" (most-viewed). One of: `relevance`, `popular`. Default `"relevance"`. |
| `uploadDate` | string | no | Filter by upload recency. Omit for any time. One of: `today`, `this_week`, `this_month`, `this_year`. |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes |  |
| `data.nextCursor` | string or null | no | Opaque cursor for the next page of results, or null when this lane has no more. Pass it back as cursor to continue. |
| `data.videos` | array | yes |  |
| `data.videos[].authorAvatarUrl` | string | no | URL of the publishing channel's avatar image. |
| `data.videos[].authorId` | string | no | YouTube channel ID of the publishing channel. |
| `data.videos[].channel` | string | yes |  |
| `data.videos[].createdUtc` | number | no | UTC epoch timestamp in seconds (Unix time). Multiply by 1000 for a JS Date in milliseconds. |
| `data.videos[].id` | string | yes |  |
| `data.videos[].image` | string | no | URL of the video thumbnail image, tracking query parameters stripped. |
| `data.videos[].lengthText` | string | yes |  |
| `data.videos[].publishedTime` | string | yes |  |
| `data.videos[].title` | string | yes |  |
| `data.videos[].url` | string | yes |  |
| `data.videos[].views` | integer | yes |  |
| `found` | boolean | yes |  |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `channel`
- `id`
- `publishedTime`
- `title`
- `url`
- `videos`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `videos` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
