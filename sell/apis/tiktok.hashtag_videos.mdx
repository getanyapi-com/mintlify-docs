List recent TikTok videos for a hashtag (creator, caption, views, likes, shares).

This page is the seller-facing summary of one catalog API, `tiktok.hashtag_videos`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$1.18 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `cursor` | string | no | Opaque pagination cursor from a previous response's nextCursor. Omit for the first page; pass it to fetch the next page of videos. |
| `hashtag` | string | yes | TikTok hashtag to fetch videos for, without the # prefix (e.g. booktok). |
| `limit` | integer | no | Maximum number of results to return (1-20, default 20). |
| `requireFields` | array | no | Optional; omit it and routing is unchanged, with the cheapest source serving. Name the output fields this request must be able to return, for example `playCount`, and it is served only by a source that returns every one of them. Fields you do not name are still returned whenever the serving source has them. This can raise your price: when the cheapest source cannot return a named field, a dearer source serves, and you are quoted and charged its price. A named field can still be absent on a video that genuinely lacks it. Naming a combination that no single source returns together is refused as invalid input, with no charge. A source that returns only a rounded or shortened value for a field does not count as returning it. On a paginated walk it applies to the first page only; later pages stay with the source that page chose, at the price it was quoted. |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes |  |
| `data.items` | array | yes | Recent TikTok video records for the hashtag. |
| `data.items[].authorFollowers` | integer or null | no | The author's follower count at the time of the request; the serving source may round large counts. Null when the serving source does not report it. |
| `data.items[].authorHandle` | string | no | Username of the video's creator, without the @ prefix. Empty when the upstream omits it. |
| `data.items[].authorImage` | string | no | Author's avatar image URL. Signed and short-lived, so the query string is load-bearing and kept intact. |
| `data.items[].authorName` | string | no | Author's display name. |
| `data.items[].authorUserId` | string | no | Author's numeric TikTok user id. |
| `data.items[].authorVerified` | boolean | no | Whether the author's account carries a TikTok verification badge. |
| `data.items[].collectCount` | integer | no | Number of times the video was saved. |
| `data.items[].commentCount` | integer | no | Number of comments on the video. Some sources round large counts (27.7M instead of 27,712,408); name the field in requireFields to be served only by a source that returns the exact count. |
| `data.items[].createdUtc` | number | yes | UTC epoch timestamp in seconds (Unix time). Multiply by 1000 for a JS Date in milliseconds. |
| `data.items[].durationSeconds` | number | no | Video duration in seconds. |
| `data.items[].hashtags` | array | no | Hashtags carried in the caption, without the leading #. Empty when the post uses none; @-mentions are excluded. |
| `data.items[].id` | string | yes | The video's numeric TikTok ID, as a string. |
| `data.items[].image` | string | no | URL of the video's cover/thumbnail image. Signed and short-lived, so the query string is load-bearing and kept intact. Empty when the upstream omits it. |
| `data.items[].likeCount` | integer | no | Number of likes on the video. Some sources round large counts (27.7M instead of 27,712,408); name the field in requireFields to be served only by a source that returns the exact count. |
| `data.items[].playCount` | integer | no | Number of views/plays of the video. Some sources round large counts (27.7M instead of 27,712,408); name the field in requireFields to be served only by a source that returns the exact count. |
| `data.items[].shareCount` | integer | no | Number of shares of the video. Some sources round large counts (27.7M instead of 27,712,408); name the field in requireFields to be served only by a source that returns the exact count. |
| `data.items[].soundAuthor` | string or null | no | Credited author of the sound. Null when the serving source does not report it. |
| `data.items[].soundClipId` | string or null | no | Id of the sound the video uses. Pass it to tiktok.song or tiktok.song_videos as clipId. Null when the serving source does not report it. |
| `data.items[].soundTitle` | string or null | no | Name of the sound. "original sound" means the creator's own audio rather than a licensed track. Null when the serving source does not report it. |
| `data.items[].text` | string | no | The video caption text. Empty for videos with no caption. |
| `data.items[].url` | string | yes | Canonical tiktok.com URL of the video, with tracking query params stripped. |
| `data.items[].videoUrl` | string | no | Playable video URL. Signed and short-lived, so the query string is load-bearing and kept intact. |
| `data.nextCursor` | string or null | no | Opaque cursor for the next page of videos, or null when there are no more. Pass it back as cursor to continue. |
| `found` | boolean | yes | Whether any videos were returned for the hashtag. |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `hashtags`
- `id`
- `items`
- `url`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `items` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.

```json

}
```
