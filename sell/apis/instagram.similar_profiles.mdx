List the related profiles Instagram's website shows for a public profile, with each account's handle, display name, verified flag and avatar. This is Instagram's shorter web list: it often holds only a few accounts and can be empty even for a large profile. When it comes back empty or cannot be read, the accounts Instagram's app suggests for the profile may be returned instead. For the full list of accounts Instagram suggests as similar, use instagram.suggested_profiles.

This page is the seller-facing summary of one catalog API, `instagram.similar_profiles`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes |  |
| `data.profiles` | array | yes | Accounts Instagram's website lists as related to the requested profile. |
| `data.profiles[].avatarUrl` | string | yes | Profile picture URL, as Instagram's CDN serves it. |
| `data.profiles[].displayName` | string | yes | Account display name. |
| `data.profiles[].private` | boolean or null | yes | Whether the account is private. Null when the source does not report it. |
| `data.profiles[].userId` | string | yes | Instagram's numeric account id, as a string. |
| `data.profiles[].username` | string | yes | Instagram username without the leading @. |
| `data.profiles[].verified` | boolean | yes | Whether the account carries Instagram's verified badge. |
| `found` | boolean | yes |  |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `profiles`
- `username`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `profiles` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
