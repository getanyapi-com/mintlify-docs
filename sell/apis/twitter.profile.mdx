Fetch a Twitter/X account's public profile (followers, tweets, bio, verification) by handle.

This page is the seller-facing summary of one catalog API, `twitter.profile`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$0.22 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `handle` | string | yes | Twitter/X handle without the leading @. |

## Fields that must never come back empty

- `avatarUrl`
- `bio`
- `displayName`
- `handle`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `pinnedPostIds` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.

## Example request

```json
{
  "handle": "nasa"
}
```

The compatibility checks fire the schema's example at your endpoint. After that, your answers are graded against what the currently serving source returned for the same real customer inputs.

## Behavior

- The input is a handle with no leading @, and username is accepted as another spelling of handle.
- There is no empty result: a handle with no account behind it returns found false with data null.
- A found profile always carries handle, displayName, followers, following, tweets, bio, verified, avatarUrl and website, using an empty string or zero for a value the account has not set rather than dropping the key.
- createdUtc is the account creation time as a UTC epoch in seconds, not a date string.
