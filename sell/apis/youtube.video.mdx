Fetch a YouTube video or Short's metadata (title, channel, views, likes, duration, publish date) by URL or ID.

This page is the seller-facing summary of one catalog API, `youtube.video`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$0.90 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

This API takes no input fields.

<Accordion title="Full input JSON Schema">

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://getanyapi.com/schemas/youtube.video.input.json",
  "example": {
    "url": "https://www.youtube.com/watch?v=dQw4w9WgXcQ"
  },
  "title": "YouTube video input",
  "type": "object",
  "additionalProperties": false,
  "properties": {
    "url": {
      "type": "string",
      "description": "Full YouTube video URL. Shorts (youtube.com/shorts/...), youtu.be, live, and embed URLs all work."
    },
    "id": {
      "type": "string",
      "description": "YouTube video ID. A Short uses the same ID as any other video."
    }
  },
  "anyOf": [
    {
      "required": [
        "url"
      ]
    },
    {
      "required": [
        "id"
      ]
    }
  ]
}
```

</Accordion>

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes | The video result, or null when not found. |
| `data.authorAvatarUrl` | string | no | URL of the publishing channel's avatar image. |
| `data.authorId` | string | no | YouTube channel ID of the publishing channel. |
| `data.authorUrl` | string | no | Canonical URL of the publishing channel, tracking query parameters stripped. |
| `data.category` | string | no | YouTube category the video is filed under, for example "Music". |
| `data.channel` | string | yes | Name of the channel that published the video. |
| `data.comments` | integer | yes | Number of comments. |
| `data.createdUtc` | number | yes | UTC epoch timestamp in seconds (Unix time). Multiply by 1000 for a JS Date in milliseconds. |
| `data.description` | string | no | Full video description text. |
| `data.durationMs` | integer | yes | Duration of the video in milliseconds. |
| `data.id` | string | yes | Unique identifier of the video. |
| `data.image` | string | no | URL of the video thumbnail image. |
| `data.keywords` | array | no | Keywords the uploader tagged the video with. |
| `data.likes` | integer | yes | Number of likes. |
| `data.title` | string | yes | Title of the video. |
| `data.views` | integer | yes | Number of views. |
| `found` | boolean | yes | Whether the video was found. |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `channel`
- `createdUtc`
- `id`
- `title`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `keywords` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
