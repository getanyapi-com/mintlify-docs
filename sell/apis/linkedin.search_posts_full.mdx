Search public LinkedIn posts with rich author, engagement, attachment, and poll details.

This page is the seller-facing summary of one catalog API, `linkedin.search_posts_full`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$5.00 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `authorCompanyNames` | array | no | Only return posts by people associated with these company names. |
| `authorIndustryIds` | array | no | Only return posts by authors associated with these LinkedIn industry IDs. |
| `authorKeywords` | string | no | Only return posts whose author profile headline or job title contains at least one of these keywords. |
| `authorUrls` | array | no | Only return posts authored by these LinkedIn profile or company URLs. |
| `contentType` | string | no | Only return posts carrying this content type. One of: `all`, `videos`, `images`, `jobs`, `live-videos`, `documents`, `collaborative-articles`. |
| `datePosted` | string | no | Only return posts published within this relative time window. Last-hour and windows beyond one month route to the provider that supports them. One of: `last-hour`, `last-day`, `last-week`, `last-month`, `last-three-months`, `last-six-months`, `last-year`. Default `"last-day"`. |
| `limit` | integer | no | Maximum number of posts to return (1-100, default 10). The upper bound is one LinkedIn search page. Default `10`. |
| `mentioningMemberUrls` | array | no | Only return posts mentioning these LinkedIn member profile URLs. |
| `query` | string | yes | LinkedIn post search query, including quoted terms or Boolean operators accepted by LinkedIn search. |
| `sort` | string | no | Order results by search relevance or publication date. One of: `relevance`, `date`. Default `"relevance"`. |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes | The matching LinkedIn posts, or null when no result was found. |
| `data.posts` | array | yes | LinkedIn posts matching the search query. |
| `data.posts[].attachmentDescription` | string | no | Short description of the attached content, as LinkedIn shows it on the preview card. Best effort on article attachments: depending on the search it may be absent, so treat it as optional. To read an article's content reliably, pass attachmentUrl to the linkedin.article endpoint. |
| `data.posts[].attachmentImage` | string | no | Image URL associated with the attachment. |
| `data.posts[].attachmentSubtitle` | string | no | Subtitle of the attached structured content. |
| `data.posts[].attachmentTitle` | string | no | Title of the attached article, job, or other structured content. |
| `data.posts[].attachmentType` | string | no | Kind of structured content attached to the post, such as article, job, poll, video, or document. |
| `data.posts[].attachmentUrl` | string | no | Canonical destination URL of the attachment. When attachmentType is article, pass this URL to the linkedin.article endpoint to read the article's full body text. |
| `data.posts[].author` | object | yes | Public author identity attached to the post. |
| `data.posts[].author.headline` | string | no | Public headline or company follower summary for the author. |
| `data.posts[].author.id` | string | no | LinkedIn identifier for the author. |
| `data.posts[].author.image` | string | no | Public profile or company image URL for the author. |
| `data.posts[].author.name` | string | no | Display name of the author. |
| `data.posts[].author.profileUrl` | string | no | Canonical LinkedIn profile or company URL for the author. |
| `data.posts[].author.publicIdentifier` | string | no | LinkedIn public identifier (vanity slug) for the author, for example "williamhgates". Stable across lanes, unlike the raw id. |
| `data.posts[].author.type` | string | no | Kind of LinkedIn entity that authored the post, derived from the author URL. One of: `person`, `company`, `showcase`. |
| `data.posts[].createdUtc` | number | yes | UTC epoch timestamp in seconds (Unix time). Multiply by 1000 for a JS Date in milliseconds. |
| `data.posts[].engagement` | object | yes | Public engagement totals attached to the post. |
| `data.posts[].engagement.breakdown` | array | no | Reaction counts grouped by LinkedIn reaction type. |
| `data.posts[].engagement.breakdown[].count` | integer | yes | Number of reactions of this type. |
| `data.posts[].engagement.breakdown[].type` | string | yes | LinkedIn reaction type. |
| `data.posts[].engagement.comments` | integer | no | Total comment count. |
| `data.posts[].engagement.reactions` | integer | no | Total reaction count. |
| `data.posts[].engagement.reposts` | integer | no | Total repost or share count. |
| `data.posts[].id` | string | yes | Stable LinkedIn activity identifier for the post. |
| `data.posts[].pollClosed` | boolean | no | Whether the attached poll is closed. |
| `data.posts[].pollOptions` | array | no | Options and public vote counts for an attached poll. |
| `data.posts[].pollOptions[].text` | string | yes | Poll option text. |
| `data.posts[].pollOptions[].votes` | integer | yes | Votes recorded for this option. |
| `data.posts[].pollQuestion` | string | no | Question asked by an attached LinkedIn poll. |
| `data.posts[].pollTotalVotes` | integer | no | Total votes recorded by the attached poll. |
| `data.posts[].text` | string | yes | Text content of the post. Empty string when the post carries no commentary of its own, such as a bare article share or an image-only post. |
| `data.posts[].url` | string | yes | Canonical URL of the LinkedIn post. |
| `found` | boolean | yes | Whether matching LinkedIn posts were found. |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `author`
- `createdUtc`
- `engagement`
- `id`
- `posts`
- `text`
- `url`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `posts` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
