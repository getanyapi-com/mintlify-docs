Get up to the requested limit of tweets and replies authored by an X (Twitter) account, with engagement, views, language, and cursor pagination where available.

This page is the seller-facing summary of one catalog API, `twitter.user_tweets`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$0.50 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `cursor` | string | no | Opaque pagination cursor from a previous response's nextCursor. Omit for the first page. |
| `handle` | string | yes | Twitter/X handle without the leading @. |
| `limit` | integer | no | Maximum number of authored tweets and replies to return in THIS page (1-100). Sources return fewer - most cap at 20 - so read `nextCursor` and pass it back as `cursor` to walk further rather than asking for one large page. Default `20`. |
| `requireFields` | array | no | Optional; omit it and routing is unchanged, with the cheapest source serving. Name the output fields this request must be able to return, for example `isPinned` or `nextCursor`, and it is served only by a source that returns every one of them. Fields you do not name are still returned whenever the serving source has them. This can raise your price: when the cheapest source cannot return a named field, a dearer source serves, and you are quoted and charged its price. A named field can still be absent on a post that genuinely lacks it. Naming a combination that no single source returns together is refused as invalid input, with no charge. On a paginated walk it applies to the first page only; later pages stay with the source that page chose, at the price it was quoted. |
| `requireSinglePage` | boolean | no | Require a lane that can return the requested limit in one response. |

## Fields that must never come back empty

- `createdUtc`
- `id`
- `text`
- `tweets`
- `url`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `tweets` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.

## Example request

```json
{
  "handle": "levelsio",
  "limit": 20
}
```

The compatibility checks fire the schema's example at your endpoint. After that, your answers are graded against what the currently serving source returned for the same real customer inputs.

## Behavior

- This timeline is the posts and the replies the account authored, so a reply it wrote belongs in the results and isReply marks it.
- Reposts are not part of this timeline: return only what the account wrote itself. twitter.user_posts is the API that carries reposts.
- isPinned has three states: true or false when the serving source publishes it, and null when it does not. Never answer false to mean unknown.
- found false covers only a handle that cannot be resolved or an account whose posts are not available; an account with nothing to return is found true with an empty tweets array.
- limit is a per-page maximum of 1 to 100 and most sources return about 20, so a caller walks further with nextCursor rather than asking for one large page.
- nextCursor is null when the page just served is the last one available.
