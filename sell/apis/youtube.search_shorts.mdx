Search YouTube Shorts by keyword and get matching Shorts (title, views, URL) with cursor pagination as normalized JSON.

This page is the seller-facing summary of one catalog API, `youtube.search_shorts`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$1.20 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `cursor` | string | no | Continuation token from a previous response for pagination. |
| `query` | string | yes | The keyword to search Shorts for. |
| `sortBy` | string | no | Sort order: "relevance" (default) or "popular" (most-viewed). One of: `relevance`, `popular`. Default `"relevance"`. |
| `uploadDate` | string | no | Filter by upload recency. Omit for any time. One of: `today`, `this_week`, `this_month`, `this_year`. |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes |  |
| `data.nextCursor` | string or null | no | Opaque cursor for the next page of results, or null when there are no more. Pass it back as cursor to continue. |
| `data.shorts` | array | yes |  |
| `data.shorts[].contentType` | string | yes | Always "short": every row here comes from YouTube's Shorts shelf. |
| `data.shorts[].id` | string | yes | YouTube video id of the Short. |
| `data.shorts[].title` | string | yes | Title of the Short. |
| `data.shorts[].url` | string | yes | Watch URL for the Short. |
| `data.shorts[].views` | integer | yes | View count, or 0 when the source did not publish one. Read viewsAvailable before trusting a 0. Rounded as YouTube shows it on Shorts (8.9M, 875K), so counts of 1,000 or more are approximate. |
| `data.shorts[].viewsAvailable` | boolean | yes | False when the source published no view count, so views is a placeholder rather than a measured zero. |
| `found` | boolean | yes |  |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `id`
- `shorts`
- `title`
- `url`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `shorts` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
