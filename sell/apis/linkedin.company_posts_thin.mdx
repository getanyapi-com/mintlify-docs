Post text and link only. No engagement counts, author details, media, or reaction breakdown - for those use linkedin.company_posts.

This page is the seller-facing summary of one catalog API, `linkedin.company_posts_thin`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$1.20 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

| Field | Type | Required | What it means |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes | The company posts result, or null when not found. |
| `data.items` | array | yes | The company's recent posts. |
| `data.items[].createdUtc` | number | yes | UTC epoch timestamp in seconds (Unix time). Multiply by 1000 for a JS Date in milliseconds. |
| `data.items[].id` | string | yes | Unique identifier of the post. |
| `data.items[].text` | string | yes | Text content of the post. |
| `data.items[].url` | string | yes | Canonical URL of the post. |
| `found` | boolean | yes | Whether the company posts were found. |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `createdUtc`
- `id`
- `items`
- `text`
- `url`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `items` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.

## Example request

```json
{
  "url": "https://www.linkedin.com/company/stripe"
}
```

The registration tests send this example to your endpoint, with the API's other test inputs. After that, the real-request check sends your endpoint real past customer inputs, and an AI reviewer compares each answer with AnyAPI's own answer to the same input.
