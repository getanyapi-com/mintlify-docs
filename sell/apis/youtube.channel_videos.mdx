List a YouTube channel's videos by handle or channel ID with cursor pagination (title, views, length, publish time).

This page is the seller-facing summary of one catalog API, `youtube.channel_videos`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$0.80 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes |  |
| `data.nextCursor` | string or null | yes | Opaque cursor for the next page of videos, or null when this lane has no more. Pass it back as cursor to continue. |
| `data.videos` | array | yes |  |
| `data.videos[].createdUtc` | number | no | UTC epoch timestamp in seconds (Unix time). Some sources only show a relative age such as "4 days ago", so the value is estimated from it and can be off by up to the label's unit (a day, a week, a month); name `createdUtc` in requireFields to be served only by a source that returns the exact time. Multiply by 1000 for a JS Date in milliseconds. |
| `data.videos[].id` | string | yes |  |
| `data.videos[].image` | string | no | URL of the video thumbnail image, tracking query parameters stripped. |
| `data.videos[].lengthText` | string or null | yes | Video length as YouTube shows it, such as 11:56, or null when the serving source does not report it. |
| `data.videos[].publishedTime` | string | yes |  |
| `data.videos[].title` | string | yes |  |
| `data.videos[].url` | string | yes |  |
| `data.videos[].views` | integer | yes | Number of views. Some sources round large counts (6.4M instead of 6,474,059); name `views` in requireFields to be served only by a source that returns the exact count. |
| `found` | boolean | yes |  |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `id`
- `publishedTime`
- `title`
- `url`
- `videos`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `videos` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
