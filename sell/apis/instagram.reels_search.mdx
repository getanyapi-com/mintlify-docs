Search Instagram Reels by keyword against Instagram's own reels search and get matching reels with view, like and comment counts, caption, creator and duration. Results are relevance-ranked, not chronological, and a page can repeat reels from the page before it. For a web-search-index view of the same keyword, with a recency filter and numbered pages, use instagram.web_reels_search.

This page is the seller-facing summary of one catalog API, `instagram.reels_search`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `cursor` | string | no | Pagination cursor from a previous response's nextCursor. |
| `query` | string | yes | Search keyword (e.g. "crossfit"). |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes | Wrapper holding the reels array, or null when nothing was found. |
| `data.nextCursor` | string or null | yes | Opaque cursor for the next page of reels, or null when this lane has no more. Pass it back as cursor to continue. Instagram relevance-ranks reels search, so a later page can repeat reels from an earlier one. |
| `data.reels` | array | yes | Reels matching the search. |
| `data.reels[].avatarUrl` | string | no | Profile picture URL of the author. |
| `data.reels[].caption` | string | yes | Reel caption text. |
| `data.reels[].comments` | integer | yes | Number of comments on the reel. |
| `data.reels[].createdUtc` | number | yes | UTC epoch timestamp in seconds (Unix time). Multiply by 1000 for a JS Date in milliseconds. |
| `data.reels[].displayName` | string | no | Display name of the author. |
| `data.reels[].durationSeconds` | number | yes | Reel duration in seconds. |
| `data.reels[].hasAudio` | boolean | no | True when the reel carries an audio track. |
| `data.reels[].id` | string | no | Reel media identifier. |
| `data.reels[].likes` | integer | yes | Number of likes on the reel. |
| `data.reels[].paidPartnership` | boolean | yes | True when the reel is a paid partnership. |
| `data.reels[].productType` | string | no | Instagram product type of the media, for example clips. |
| `data.reels[].shortcode` | string | yes | Instagram media shortcode. |
| `data.reels[].thumbnail` | string | yes | URL of the reel thumbnail image. |
| `data.reels[].url` | string | yes | Canonical URL of the reel. |
| `data.reels[].userId` | string | no | Instagram user id of the author. |
| `data.reels[].username` | string | yes | Username of the account that posted the reel. |
| `data.reels[].verified` | boolean | yes | True when the posting account is verified. |
| `data.reels[].videoUrl` | string | no | Direct URL to the reel video. |
| `data.reels[].views` | integer | no | Play count of the reel. |
| `found` | boolean | yes | True when matching reels were found; false when the search returned nothing. |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `caption`
- `reels`
- `shortcode`
- `thumbnail`
- `url`
- `username`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `reels` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
