Get TikTok Shop search autocomplete terms for a keyword: the long-tail queries shoppers actually type, for keyword and demand research.

This page is the seller-facing summary of one catalog API, `tiktok_shop.search_suggestions`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$1.20 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `country` | string | no | Two-letter country code of the TikTok Shop market (e.g. US). Default `"US"`. |
| `language` | string | no | Language tag for the suggestions (e.g. en-US). Default `"en-US"`. |
| `query` | string | yes | Seed keyword to expand (e.g. ashwagandha gummies). |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes |  |
| `data.suggestions` | array | yes | Autocomplete terms TikTok Shop suggests for the seed keyword, most relevant first. |
| `found` | boolean | yes |  |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `suggestions`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `suggestions` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
