Search TikTok by keyword and get matching videos (caption, views, likes, comments, shares) as normalized JSON.

This page is the seller-facing summary of one catalog API, `tiktok.search_keyword`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$0.60 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `cursor` | string | no | Pagination cursor from a previous response. |
| `datePosted` | integer or string | no | Time frame filter, in days back from now. Use a canonical JSON integer that is nonnegative: 0 for any time, 1 for the past 24 hours, 7 for the past week, 30 for the past month, 90 for the past three months, or 180 for the past six months. Any other number is not guaranteed to filter anything. Legacy numeric strings remain accepted. Default `0`. |
| `query` | string | yes | The keyword to search TikTok for. |
| `requireCursor` | boolean | no | Deprecated: name `nextCursor` in `requireFields` instead, which is the field this flag is translated into. It stays accepted so callers that already send it keep working. Sending it routes you to a source that returns a pagination cursor, which can raise your price when the cheapest source cannot page. |
| `requireFields` | array | no | Optional; omit it and routing is unchanged, with the cheapest source serving. Name the output fields this request must be able to return, for example `nextCursor`, and it is served only by a source that returns every one of them. Fields you do not name are still returned whenever the serving source has them. This can raise your price: when the cheapest source cannot return a named field, a dearer source serves, and you are quoted and charged its price. A named field can still be absent on a record that genuinely lacks it. Naming a combination that no single source returns together is refused as invalid input, with no charge. |
| `sortBy` | string | no | Sort order: relevance, most-liked, date-posted. One of: `relevance`, `most-liked`, `date-posted`. Default `"relevance"`. |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes |  |
| `data.nextCursor` | string or null | no | Opaque cursor for the next page of videos, or null when this lane has no more. Pass it back as cursor to continue. |
| `data.videos` | array | yes |  |
| `data.videos[].author` | string | no | Username (handle) of the account that posted, without the @ prefix. |
| `data.videos[].authorFollowers` | integer or null | no | The author's follower count at the time of the request. Null when the serving source does not report it. |
| `data.videos[].authorImage` | string | no | Author's avatar image URL. Signed and short-lived, so the query string is load-bearing and kept intact. |
| `data.videos[].authorName` | string | no | Author's display name. |
| `data.videos[].authorUserId` | string | no | Author's numeric TikTok user id. |
| `data.videos[].authorVerified` | boolean or null | no | Whether the author's account carries a TikTok verification badge. Null when the serving source does not report it. |
| `data.videos[].caption` | string | yes |  |
| `data.videos[].comments` | integer | yes |  |

## Fields that must never come back empty

- `authorImage`
- `authorName`
- `authorUserId`
- `caption`
- `hashtags`
- `id`
- `image`
- `soundClipId`
- `url`
- `videos`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `videos` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
