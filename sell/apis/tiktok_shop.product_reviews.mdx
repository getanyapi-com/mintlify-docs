Fetch customer reviews for a TikTok Shop product by URL (rating, text, reviewer, country, and verified-purchase flag).

This page is the seller-facing summary of one catalog API, `tiktok_shop.product_reviews`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$0.95 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `page` | integer | no | 1-based results page. Use with hasMore in the output to paginate. Default `1`. |
| `region` | string | no | Two-letter country code of the product's shop region (e.g. US). Strongly recommended for correct results. |
| `requireFields` | array | no | Optional; omit it and routing is unchanged, with the cheapest source serving. Name the output fields this request must be able to return, for example `rating`, and it is served only by a source that returns every one of them. Fields you do not name are still returned whenever the serving source has them. This can raise your price: when the cheapest source cannot return a named field, a dearer source serves, and you are quoted and charged its price. A named field can still be empty on a review that genuinely lacks it. Naming a combination that no single source returns together is refused as invalid input, with no charge. |
| `url` | string | yes | TikTok Shop product URL (e.g. https://www.tiktok.com/shop/pdp/.../1729385633899532161). |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes | Wrapper holding the reviews array plus totals, or null when nothing was found. |
| `data.hasMore` | boolean | yes | True when more reviews are available beyond this page. |
| `data.rating` | number or null | yes | Overall product score (1-5), or null when the serving source does not report it. |
| `data.reviews` | array | yes | Product reviews. |
| `data.reviews[].avatarUrl` | string | no | Reviewer's avatar image URL. Signed and short-lived, so the query string is load-bearing and kept intact. |
| `data.reviews[].country` | string | yes | Reviewer's country code. |
| `data.reviews[].createdUtc` | number | yes | Review time as epoch milliseconds. |
| `data.reviews[].id` | string | yes | Review identifier. |
| `data.reviews[].images` | array | no | Photos the reviewer attached, as image URLs; empty when the review has none. Some are signed and short-lived, so the query string is kept intact. Omitted when the serving source does not report review photos. |
| `data.reviews[].productId` | string | no | Identifier of the reviewed product. |
| `data.reviews[].rating` | number | yes | Star rating for this review (1-5). |
| `data.reviews[].reviewerName` | string | yes | Display name of the reviewer. |
| `data.reviews[].sku` | string | yes | Variant bought, e.g. "Color: Black". |
| `data.reviews[].text` | string | yes | Review text content. |
| `data.reviews[].verifiedPurchase` | boolean | yes | True when the review is from a verified purchase. |
| `data.totalReviews` | integer or null | yes | Total number of reviews for the product, or null when the serving source does not report it. |
| `found` | boolean | yes | True when reviews were found; false when the lookup returned nothing. |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `createdUtc`
- `id`
- `reviewerName`
- `reviews`
- `sku`
- `text`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `reviews` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
