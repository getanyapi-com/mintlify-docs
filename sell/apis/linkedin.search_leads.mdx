LinkedIn lead search with Sales Navigator's search and filters: one call returns a page of up to 25 people matching a keyword and Sales Navigator lead filters (location, job title, current and past company, school, seniority, function, company size, and more), or the results of a Sales Navigator lead-search URL you built yourself. Each lead comes with name, current positions, location, summary, and photo, and its url opens the profile and can be passed to linkedin.profile for the full record. For full profiles in one call use linkedin.search_profiles.

This page is the seller-facing summary of one catalog API, `linkedin.search_leads`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$70.00 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes | The results wrapper, or null when nothing matched. |
| `data.items` | array | yes | Matching leads, up to 25 per page. |
| `data.items[].about` | string | no | Profile summary text, when the member wrote one. |
| `data.items[].currentPositions` | array | no | Current roles. |
| `data.items[].currentPositions[].companyId` | string | no | LinkedIn company id. |
| `data.items[].currentPositions[].companyLinkedinUrl` | string | no | LinkedIn company page URL. |
| `data.items[].currentPositions[].companyName` | string | no | Company name. |
| `data.items[].currentPositions[].startedOn` | object | no | When the role started, as `month` (1-12, when shown) and `year`. |
| `data.items[].currentPositions[].tenureAtCompany` | object | no | Time at this company, as `numYears` and `numMonths`. |
| `data.items[].currentPositions[].tenureAtPosition` | object | no | Time in this role, as `numYears` and `numMonths`. |
| `data.items[].currentPositions[].title` | string | no | Job title. |
| `data.items[].firstName` | string | no | Member's first name. |
| `data.items[].id` | string | no | LinkedIn member id, the last segment of `url`. |
| `data.items[].image` | string | no | Profile picture URL. The query string is a signed token, so keep the URL intact. |
| `data.items[].lastName` | string | no | Member's last name. |
| `data.items[].location` | string | no | Member's location as a single string (city, region, country). |
| `data.items[].openProfile` | boolean | no | Whether the member accepts messages from people outside their network. |
| `data.items[].premium` | boolean | no | Whether the member has a LinkedIn Premium subscription. |
| `data.items[].url` | string | yes | LinkedIn profile URL in its member-id form (https://www.linkedin.com/in/ACwAAA...). It opens the profile on LinkedIn, and passing it as `url` to linkedin.profile returns the full record. |
| `data.page` | integer | no | The page this response holds, starting at 1. |
| `data.totalPages` | integer | no | How many pages of up to 25 leads the search has. |
| `data.totalResults` | integer | no | How many leads match the search in total, across every page. |
| `found` | boolean | yes | True when the page returned at least one lead. |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `currentPositions`
- `firstName`
- `image`
- `items`
- `lastName`
- `location`
- `url`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `items` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
