Fetch a TikTok creator's public profile (followers, likes, bio, verification) by handle.

This page is the seller-facing summary of one catalog API, `tiktok.profile`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$0.45 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `handle` | string | yes | TikTok username without the leading @ (e.g. "stoolpresidente"). |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes |  |
| `data.avatarUrl` | string | yes |  |
| `data.bio` | string | yes |  |
| `data.createdUtc` | number | no | UTC epoch timestamp in seconds (Unix time). Multiply by 1000 for a JS Date in milliseconds. |
| `data.displayName` | string | yes |  |
| `data.externalUrl` | string | no | The single link the account publishes in its bio, normalized to an absolute URL. Absent when the account publishes no link. |
| `data.followers` | integer | yes |  |
| `data.following` | integer | yes |  |
| `data.handle` | string | yes |  |
| `data.likes` | integer | yes |  |
| `data.private` | boolean | no | Whether the account is private. |
| `data.secUid` | string | no | TikTok's sec_uid: the opaque account identifier TikTok's own web and app endpoints key on, and the id most third-party TikTok tools ask for. |
| `data.userId` | string | no | TikTok's numeric internal user id for the account. Unlike the handle it never changes, so store it as the account's key. |
| `data.verified` | boolean | yes |  |
| `data.videos` | integer | yes |  |
| `found` | boolean | yes |  |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `avatarUrl`
- `bio`
- `displayName`
- `externalUrl`
- `handle`
- `userId`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty result is not a not-found: when the entity exists but carries nothing, answer 2xx with `found: true` and the empty values.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
