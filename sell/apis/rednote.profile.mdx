Look up a RedNote (Xiaohongshu) profile by user ID and return normalized profile details.

This page is the seller-facing summary of one catalog API, `rednote.profile`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$10.00 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `requireFields` | array | no | Optional; omit it and routing is unchanged, with the cheapest source serving. Name the output fields this request must be able to return, for example `verifyType`, and it is served only by a source that returns every one of them. Fields you do not name are still returned whenever the serving source has them. This can raise your price: when the cheapest source cannot return a named field, a dearer source serves, and you are quoted and charged its price. A named field can still be absent on a profile that genuinely lacks it. Naming a combination that no single source returns together is refused as invalid input, with no charge. |
| `userId` | string | yes | RedNote (Xiaohongshu) user ID. |

## Fields that must never come back empty

- `description`
- `image`
- `location`
- `nickname`
- `redId`
- `shareUrl`
- `userId`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.

## Example request

```json
{
  "userId": "56b0a4491c07df6365277af7"
}
```

The registration tests send this example to your endpoint, with the API's other test inputs. After that, the real-request check sends your endpoint real past customer inputs, and an AI reviewer compares each answer with AnyAPI's own answer to the same input.
