Fetch a rich LinkedIn member profile by URL: name, headline, avatar, location, connections and followers, current position, and full work experience with job titles, descriptions, dates, employment/workplace type, and per-role skills, plus education, skills, certifications, honors and awards, languages, projects, publications, and verified/premium/open-to-work flags.

This page is the seller-facing summary of one catalog API, `linkedin.profile`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$4.00 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `url` | string | yes | Full LinkedIn profile URL. |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes | The profile result, or null when not found. |
| `data.about` | string | no | About/summary text of the profile. |
| `data.certifications` | array | no | Licenses and certifications. |
| `data.certifications[].issuedAt` | string | no | Issue date text. |
| `data.certifications[].issuedBy` | string | no | Issuing organization. |
| `data.certifications[].title` | string | no | Certification title. |
| `data.city` | string | no | City of the profile owner. |

| `data.currentPosition` | array | no | The member's current role(s). |
| `data.currentPosition[].companyId` | string | no | LinkedIn's numeric company id, as a string. |
| `data.currentPosition[].companyLinkedinUrl` | string | no | Company LinkedIn URL. |

| `data.experience[].companyLinkedinUrl` | string | no | Company LinkedIn URL. |
| `data.experience[].companyName` | string | no | Company name. |
| `data.experience[].description` | string | no | Role description. |
| `data.experience[].duration` | string | no | Human-readable tenure, e.g. '3 yrs 2 mos'. |
| `data.experience[].employmentType` | string | no | Employment type, e.g. 'Full-time'. |
| `data.experience[].endDate` | string | no | End date text, e.g. 'Present'. |
| `data.experience[].location` | string | no | Role location. |
| `data.experience[].position` | string | yes | Job title. |
| `data.experience[].skills` | array | no | Skills associated with this role. |
| `data.experience[].startDate` | string | no | Start date text, e.g. 'Feb 2014'. |
| `data.experience[].workplaceType` | string | no | Workplace type, e.g. 'Remote' or 'On-site'. |
| `data.firstName` | string | yes | First name of the profile owner. |
| `data.followerCount` | integer | no | Number of followers. |
| `data.headline` | string | yes | Professional headline shown under the name. |
| `data.hiring` | boolean | no | Whether the member shows the Hiring badge. |
| `data.honorsAndAwards` | array | no | Honors and awards. |
| `data.honorsAndAwards[].description` | string | no | Award description. |
| `data.honorsAndAwards[].issuedAt` | string | no | Issue date text. |
| `data.honorsAndAwards[].issuedBy` | string | no | Issuing organization. |
| `data.honorsAndAwards[].title` | string | no | Award title. |
| `data.id` | string | no | LinkedIn member identifier. |
| `data.influencer` | boolean | no | Whether LinkedIn marks the member as an influencer. |
| `data.languages` | array | no | Languages, as returned by LinkedIn when present. |
| `data.lastName` | string | yes | Last name of the profile owner. |
| `data.location` | string | no | Location of the profile owner. |
| `data.openToWork` | boolean | no | Whether the member is open to work. |
| `data.photo` | string | no | URL of the profile photo. |
| `data.premium` | boolean | no | Whether the member has LinkedIn Premium. |
| `data.projects` | array | no | Projects, as returned by LinkedIn when present. |
| `data.publicIdentifier` | string | no | LinkedIn public identifier (the /in/ handle). |
| `data.publications` | array | no | Publications. |
| `data.publications[].description` | string | no | Publication description. |
| `data.publications[].publishedText` | string | no | Publisher and/or date text as shown on LinkedIn. |
| `data.publications[].title` | string | no | Publication title. |
| `data.skills` | array | no | The member's skills, as free-form strings when present. |
| `data.state` | string | no | State or region of the profile owner. |
| `data.topSkills` | array | no | The member's top skills, as free-form strings when present. |
| `data.url` | string | yes | Canonical LinkedIn profile URL. |
| `data.verified` | boolean | no | Whether the profile is identity-verified. |
| `found` | boolean | yes | Whether the profile was found. |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `experience`
- `headline`
- `position`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `certifications` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.

## Example request

```json
{
  "url": "https://www.linkedin.com/in/patrickcollison"
}
```

The compatibility checks fire the schema's example at your endpoint. After that, your answers are graded against what the currently serving source returned for the same real customer inputs.
