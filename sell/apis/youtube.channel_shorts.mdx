List a YouTube channel's Shorts by handle or channel ID with cursor pagination, views, and publish timestamps.

This page is the seller-facing summary of one catalog API, `youtube.channel_shorts`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$0.98 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

This API takes no input fields.

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes | The normalized Shorts page, or null when the channel was not found. |
| `data.nextCursor` | string or null | yes | Opaque cursor for the next Shorts page, or null when no next page is available. |
| `data.shorts` | array | yes | Short-form videos returned by the provider's dedicated YouTube Shorts endpoint. |
| `data.shorts[].contentType` | string | yes | Explicit normalized provenance that this item came from a dedicated Shorts feed. One of: `short`. |
| `data.shorts[].createdUtc` | number | no | UTC epoch timestamp in seconds when supplied by the upstream response. |
| `data.shorts[].duration` | string | yes | Published duration when supplied by the upstream response. |
| `data.shorts[].id` | string | yes | Unique YouTube video identifier. |
| `data.shorts[].image` | string | no | URL of the short thumbnail image, tracking query parameters stripped. |
| `data.shorts[].likes` | integer or null | yes | Public like count, or null when the serving source does not report it. |
| `data.shorts[].title` | string | no | Public title or caption for the Short. |
| `data.shorts[].url` | string | yes | Public YouTube URL for the Short. |
| `data.shorts[].views` | integer | yes | Public view count when supplied by the upstream response. |
| `data.shorts[].viewsAvailable` | boolean | yes | Whether views is backed by a public count in the upstream response. |
| `found` | boolean | yes | Whether the channel Shorts feed was found. |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `id`
- `shorts`
- `title`
- `url`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `shorts` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
