List comments on a LinkedIn post - full text, commenter name/URL/job title, timestamps, and engagement.

This page is the seller-facing summary of one catalog API, `linkedin.post_comments`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$2.85 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `limit` | integer | no | Maximum number of comments to return. Default `100`. |
| `postedLimit` | string | no | Only return comments posted within this window (default any). One of: `any`, `24h`, `week`, `month`, `3months`, `6months`, `year`. |
| `url` | string | yes | Full URL of the LinkedIn post to list comments for. |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes | The post comments result, or null when not found. |
| `data.items` | array | yes | The post's comments. |
| `data.items[].actor` | object | no | The commenter (a profile or a company). |
| `data.items[].actor.id` | string | no | LinkedIn identifier of the commenter. |
| `data.items[].actor.image` | string | no | Profile picture URL of the commenter. |
| `data.items[].actor.linkedinUrl` | string | no | Canonical LinkedIn URL of the commenter. |
| `data.items[].actor.name` | string | no | Display name of the commenter. |
| `data.items[].actor.position` | string | no | Commenter's headline or job title as displayed. |
| `data.items[].actor.type` | string | no | Commenter kind, e.g. 'profile' or 'company'. |
| `data.items[].commentary` | string | yes | Full text of the comment. |
| `data.items[].createdUtc` | number | no | UTC epoch timestamp in seconds (Unix time). Multiply by 1000 for a JS Date in milliseconds. |
| `data.items[].edited` | boolean | no | Whether the comment has been edited. |
| `data.items[].engagement` | object | no | Engagement metrics for the comment. |
| `data.items[].engagement.comments` | integer | no | Number of replies to the comment. |
| `data.items[].engagement.likes` | integer | no | Number of likes on the comment. |
| `data.items[].id` | string | yes | Unique identifier of the comment. |
| `data.items[].pinned` | boolean | no | Whether the comment is pinned on the post. |
| `data.items[].url` | string | no | Canonical permalink URL of the comment. |
| `found` | boolean | yes | Whether comments were found for the post. |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `commentary`
- `createdUtc`
- `id`
- `image`
- `items`
- `linkedinUrl`
- `name`
- `position`
- `url`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `items` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
