List the comments on an Instagram post or reel by URL with cursor pagination (text, author, likes).

This page is the seller-facing summary of one catalog API, `instagram.post_comments`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$0.80 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `cursor` | string | no | Pagination cursor from a previous response's nextCursor. |
| `url` | string | yes | Full Instagram post or reel URL. |

| `data.comments` | array | yes |  |
| `data.comments[].author` | string | yes |  |
| `data.comments[].avatarUrl` | string | no | URL of the commenting account's profile avatar image. |

| `data.comments[].text` | string | yes |  |
| `data.comments[].verified` | boolean | yes |  |

## Fields that must never come back empty

- `author`
- `comments`
- `createdUtc`
- `id`
- `text`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `comments` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
