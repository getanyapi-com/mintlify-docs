LinkedIn company search with Sales Navigator's account filters: one call returns a page of up to 25 companies matching filters on industry, headquarters location, headcount, and follower count, with industries and headquarters locations to exclude. Each company comes with name, industry, size, description, and logo, and its url opens the company page and can be passed to linkedin.company for the full record. To search companies by keyword use linkedin.search_companies; to find people at matching companies use linkedin.search_leads.

This page is the seller-facing summary of one catalog API, `linkedin.search_accounts`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$70.00 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

This API takes no input fields.

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes | The results wrapper, or null when nothing matched. |
| `data.items` | array | yes | Matching companies, up to 25 per page. |
| `data.items[].description` | string | no | Company description from its LinkedIn page, when it has one. |
| `data.items[].employeeCountRange` | string | no | Company size as stated on its LinkedIn page, one of 1-10, 11-50, 51-200, 201-500, 501-1000, 1001-5000, 5001-10000, 10001+. It can differ from employeesOnLinkedInText, which counts members. |
| `data.items[].employeesOnLinkedInText` | string | no | How many LinkedIn members list the company as their employer, as LinkedIn displays the number (e.g. '144' or '220K+'). Text, not an integer, because large counts are rounded. It can fall outside the companyHeadcount band searched for. |
| `data.items[].id` | string | yes | LinkedIn company id, the last segment of `url`. |
| `data.items[].image` | string | no | Company logo image URL. The query string is a signed token, so keep the URL intact. |
| `data.items[].industry` | string | no | Company industry, as a LinkedIn industry name. |
| `data.items[].name` | string | no | Company name. |
| `data.items[].url` | string | yes | LinkedIn company page URL in its numeric-id form (https://www.linkedin.com/company/1035). It opens the company page on LinkedIn, and passing it as `url` to linkedin.company returns the full record. |
| `data.page` | integer | no | The page this response holds, starting at 1. |
| `data.totalPages` | integer | no | How many pages of up to 25 companies the search has, at most 100. |
| `data.totalResults` | integer | no | How many companies match the search in total, across every page. |
| `found` | boolean | yes | True when the page returned at least one company. |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `description`
- `employeeCountRange`
- `id`
- `image`
- `industry`
- `items`
- `name`
- `url`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `items` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
