Search TikTok Shop products by keyword across 15 countries: price, sales, rating, and seller info per product, in one normalized response.

This page is the seller-facing summary of one catalog API, `tiktok_shop.search`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$1.20 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `country` | string | no | Country code of the TikTok Shop market to search (e.g. US). One of: `US`, `VN`, `TH`, `PH`, `MY`, `ID`, `GB`, `SG`, `ES`, `MX`, `DE`, `IT`, `FR`, `BR`, `JP`. Default `"US"`. |
| `limit` | integer | no | Accepted but ignored. The search returns every product TikTok Shop gives for the query, typically about 30 and occasionally more than 50, for the same price per call. |
| `query` | string | yes | Search keyword for TikTok Shop products (e.g. wireless earbuds). |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes |  |
| `data.items` | array | yes | Product records matching the search query: id, title, price, sales count, rating, seller, and product URL. |
| `data.items[].currency` | string | no | ISO currency name, e.g. USD. |
| `data.items[].discountPct` | number | no | Discount off the original price as a percentage, e.g. 10 for 10% off. Omitted when the product is not discounted. |
| `data.items[].image` | string | no | Product image URL. |
| `data.items[].originalPrice` | number | no | Pre-discount list price (0 when not on sale). |
| `data.items[].price` | number | no | Current sale price. |
| `data.items[].productId` | string | yes | TikTok Shop product id. |
| `data.items[].rating` | number | no | Average review score. |
| `data.items[].reviewCount` | integer | no | Number of reviews. Omitted when the lane that served this request does not report it. |
| `data.items[].sellerId` | string | no | TikTok Shop seller id, for joining to the seller's other products. |
| `data.items[].shopName` | string | no | Seller shop name. |
| `data.items[].soldCount` | integer | no | Units sold. |
| `data.items[].title` | string | yes | Product title. |
| `data.items[].url` | string | no | Canonical product detail page URL. |
| `found` | boolean | yes |  |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `items`
- `productId`
- `title`
- `url`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `items` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.

## Example request

```json
{
  "query": "phone case",
  "limit": 3
}
```
