Fetch a YouTube channel's stats (subscribers, video count, total views, description) and the links on its About page, by handle or channel ID.

This page is the seller-facing summary of one catalog API, `youtube.channel`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$0.36 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes |  |
| `data.avatarUrl` | string | yes |  |
| `data.channelId` | string | yes |  |
| `data.description` | string | yes |  |
| `data.handle` | string | no | The channel's @handle, for example "@mkbhd". |
| `data.links` | array | no | The links the channel lists in the Links section of its About page, in the order shown. Empty when the channel lists none, and absent when the serving source does not report links; name `links` in requireFields to be served only by a source that does. |
| `data.links[].title` | string | no | The label the channel gave the link, when the serving source reports it. |
| `data.links[].url` | string | yes | The link's address, starting with https://. |
| `data.subscribers` | integer | yes |  |
| `data.title` | string | yes |  |
| `data.url` | string | no | Canonical URL of the channel page, tracking query parameters stripped. |
| `data.videos` | integer | yes |  |
| `data.views` | integer or null | yes | Lifetime view count across the channel's videos, or null when the serving source does not report it. |
| `found` | boolean | yes |  |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `channelId`
- `description`
- `title`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty result is not a not-found: when the entity exists but carries nothing, answer 2xx with `found: true` and the empty values.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.

