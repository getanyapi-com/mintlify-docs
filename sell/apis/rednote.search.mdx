Search RedNote (Xiaohongshu) notes by keyword and return normalized note records with pagination.

This page is the seller-facing summary of one catalog API, `rednote.search`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$10.00 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `cursor` | string | no | Pagination cursor from the previous response. |
| `query` | string | yes | Keyword to search for on RedNote (Xiaohongshu). |
| `sort` | string | no | Sort order for matching notes. One of: `general`, `hot`, `time`. Default `"general"`. |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes | Wrapper holding the notes array plus pagination, or null when nothing was found. |
| `data.nextCursor` | string or null | yes | Opaque cursor for the next page of notes, or null when this lane has no more. Pass it back as cursor to continue. |
| `data.notes` | array | yes | Notes matching the search. |
| `data.notes[].authorImage` | string | no | URL of the author's avatar. |
| `data.notes[].authorNickname` | string | no | Display name of the note author. |
| `data.notes[].authorRedId` | string | no | Author's public RedNote ID. |
| `data.notes[].authorUserId` | string | no | Identifier of the note author. |
| `data.notes[].collectCount` | integer | no | Number of times the note was collected. |
| `data.notes[].commentCount` | integer | no | Number of comments on the note. |
| `data.notes[].createdUtc` | number | no | UTC epoch timestamp in seconds (Unix time). Multiply by 1000 for a JS Date in milliseconds. |
| `data.notes[].description` | string | no | Note body text. |
| `data.notes[].image` | string | no | URL of the note cover image. |
| `data.notes[].likeCount` | integer | no | Number of likes on the note. |
| `data.notes[].noteId` | string | yes | Note identifier. |
| `data.notes[].shareCount` | integer | no | Number of times the note was shared. |
| `data.notes[].title` | string | no | Note title. |
| `data.notes[].type` | string | no | Note type, e.g. "normal" or "video". |
| `data.notes[].updatedUtc` | number | no | UTC epoch timestamp in seconds (Unix time). Multiply by 1000 for a JS Date in milliseconds. |
| `data.notes[].xsecToken` | string | no | Security token required to fetch the note's full detail. |
| `found` | boolean | yes | True when matching notes were found; false when the search returned nothing. |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `authorImage`
- `authorNickname`
- `authorRedId`
- `authorUserId`
- `description`
- `image`
- `noteId`
- `notes`
- `title`
- `type`
- `xsecToken`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

This API says what comes back as not found:

> True when matching notes were found; false when the search returned nothing.

Follow that rule: where it calls a case not found, answer with the not-found shape above. Otherwise, an empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `notes` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
