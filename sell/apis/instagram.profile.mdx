Fetch an Instagram account's public profile (followers, posts, bio, verification) by handle.

This page is the seller-facing summary of one catalog API, `instagram.profile`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$1.20 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `handle` | string | yes | Instagram username without the leading @. |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes |  |
| `data.avatarUrl` | string | yes | Profile picture URL at the highest resolution the account exposes. |
| `data.bio` | string | yes | Profile biography text. |
| `data.bioLinks` | array | no | Every link the account publishes in its bio, in the order Instagram returns them. Business accounts often list several here while externalUrl carries only the first. |
| `data.bioLinks[].title` | string | no | Display label for the link, empty when the account set none. |
| `data.bioLinks[].url` | string | yes | Destination URL, exactly as the account published it. |
| `data.category` | string | no | Instagram's category label for the account (for example "Government Agencies" or "Coffee shop"). Absent when the account publishes no category. |
| `data.contactMethod` | string | no | The contact button Instagram shows on the profile, for example CALL, TEXT, EMAIL, or UNKNOWN. Absent when the account exposes no contact button. Instagram no longer publishes the underlying email or phone number to unauthenticated callers. |
| `data.displayName` | string | yes | Account display name. |
| `data.externalUrl` | string | no | The single website link on the profile. Absent when the account publishes no link. |
| `data.followers` | integer | yes | Follower count. |
| `data.following` | integer | yes | Number of accounts this account follows. |
| `data.handle` | string | yes | Instagram username without the leading @. |
| `data.isBusiness` | boolean | no | Whether Instagram flags the account as a business account. |
| `data.posts` | integer | yes | Number of posts on the account. |
| `data.private` | boolean | yes | Whether the account is private. |
| `data.userId` | string | no | Instagram's numeric account id, as a string. |
| `data.verified` | boolean | yes | Whether the account carries Instagram's verified badge. |
| `found` | boolean | yes |  |

Extra fields are kept, missing declared fields fail.

## Fields that must never come back empty

- `avatarUrl`
- `bio`
- `bioLinks`
- `category`
- `displayName`
- `externalUrl`
- `handle`
- `userId`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `bioLinks` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.
