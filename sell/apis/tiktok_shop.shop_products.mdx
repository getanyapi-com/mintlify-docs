List every product of a TikTok Shop store by URL (title, price, sales, and rating per product plus shop-level stats) with cursor pagination.

This page is the seller-facing summary of one catalog API, `tiktok_shop.shop_products`. The transport rules that apply to every API a seller serves - signed requests, the response envelope, timeouts, and body limits - are on [the operator endpoint contract](/sell/operator-endpoint-contract).

## The price you compete with

AnyAPI publishes this API from **$1.20 per 1,000 requests**. That is the price a buyer sees today, so it is the price your endpoint has to come in under to win traffic.

## The request your endpoint receives

| Field | Type | Required | What it means |
| --- | --- | --- | --- |
| `cursor` | string | no | Opaque pagination cursor from a previous response's nextCursor. |
| `region` | string | no | Two-letter country code of the store's market (e.g. US). |
| `requireFields` | array | no | Optional; omit it and routing is unchanged, with the cheapest source serving. Name the output fields this request must be able to return, for example `shopRating`, and it is served only by a source that returns every one of them. Fields you do not name are still returned whenever the serving source has them. This can raise your price: when the cheapest source cannot return a named field, a dearer source serves, and you are quoted and charged its price. A named field can still be absent on a store that genuinely lacks it. Naming a combination that no single source returns together is refused as invalid input, with no charge. On a paginated walk it applies to the first page only; later pages stay with the source that page chose, at the price it was quoted. |
| `sortBy` | string | no | Product ordering within the store. One of: `top`, `new_releases`. Default `"top"`. |
| `url` | string | yes | TikTok Shop store URL (e.g. https://www.tiktok.com/shop/store/&lt;name&gt;/&lt;id&gt; or https://shop.tiktok.com/us/store/&lt;name&gt;/&lt;id&gt;). The link must include the store's numeric id, the long number after the store name: a link with only the name (tiktok.com/shop/store/&lt;name&gt;) does not open a store page on TikTok. A link without the store id, a vt.tiktok.com or vm.tiktok.com share link, or any link that is not a store page, is refused as invalid input, with no charge; send the store page link with its id (tiktok.com/shop/store/&lt;name&gt;/&lt;id&gt;) instead. |

## The response your endpoint must return

| Field | Type | Always present | What it means |
| --- | --- | --- | --- |
| `data` | null or object | yes |  |
| `data.hasMore` | boolean | yes |  |
| `data.nextCursor` | string or null | yes | Opaque cursor for the next page of products, or null when this lane has no more. Pass it back as cursor to continue. |
| `data.productCount` | integer or null | yes | Number of products the store has on sale, or null when the serving source does not report it. |
| `data.products` | array | yes |  |

## Fields that must never come back empty

- `productId`
- `products`
- `sellerId`
- `shopName`
- `title`
- `url`

The repository marks these fields as ones every source must be able to fill. An empty value is only correct when the entity itself genuinely has nothing there.

## Not found, and how it differs from empty

When the entity does not exist, answer 2xx with the not-found shape:

```json
{
  "found": false,
  "data": null
}
```

An empty list is not a not-found: when the entity exists and has nothing to return, answer 2xx with `found: true` and an empty `products` array.

This output schema declares no `reason` field, so `found: false` is the whole not-found answer.

## Example request

```json
{
  "url": "https://www.tiktok.com/shop/store/goli-nutrition/7495794203056835079"
```
