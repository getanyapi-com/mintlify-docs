**Operators** run their own scraper or data service behind an API in the AnyAPI catalog.
When your endpoint serves a request, you are paid 80% of what the customer paid, in USD.
The [Seller Terms](https://getanyapi.com/seller-terms) set out the full rules.

<Info>
  AI agents can run an operator account end to end from
  [`getanyapi.com/operator-onboarding/SKILL.md`](https://getanyapi.com/operator-onboarding/SKILL.md).
</Info>

## How selling works

You plug into an existing catalog API rather than list a new one. Each API has a fixed
request and response format (its *schema*). The ones you can register yourself are listed in
[APIs open to sellers](/sell/apis/index); to sell any other one, email
[support@getanyapi.com](mailto:support@getanyapi.com).

You host an HTTPS endpoint that speaks the API's format and set your own price. AnyAPI
sends each request to the cheapest source first, yours or its own, while your endpoint keeps
finishing requests as reliably.

Customers always see AnyAPI as the provider. Your operator id (`op_...`) is used for
routing, earnings, and payouts, and is never shown to buyers.

## The journey

<Warning>
  Before you go live, every seller passes an identity check (a government photo ID and a
  selfie, with our verification partner Didit) and connects PayPal to get paid. If PayPal
  isn't available to you, email [support@getanyapi.com](mailto:support@getanyapi.com) and
  we'll look at alternatives.
</Warning>

<Steps>
  <Step title="Start selling">
    In the dashboard, open [Sell APIs](https://getanyapi.com/dashboard/sell) and click
    **Start selling**, or call `POST /v1/operator/profile`. First tick **I agree to the
    Seller Terms**: you accept the [Seller Terms](https://getanyapi.com/seller-terms)
    before you can register an endpoint or run the registration tests (a person reads and
    accepts them in the dashboard). Registering an endpoint, the registration tests and the
    real-request check need no approval.

    AnyAPI approves a seller for paid traffic only once the seller profile has a name, a
    photo, and a description, or the seller has chosen to be listed anonymously. Set the name
    and description with `PATCH /v1/operator/profile` and a body of
    `{"displayName": "...", "description": "..."}`. Upload the photo as the raw request body of
    `POST /v1/operator/profile/photo`: a PNG, JPEG, or WebP image of at most 1 MB.

    To be listed anonymously, tick **List me anonymously** in the seller profile, or send
    `"anonymous": true` in the same `PATCH`. The public sellers pages then show only the animal
    name AnyAPI assigns you, never your name, photo, or description. You still pass the
    identity check and are paid the same way.
  </Step>
  <Step title="Build your endpoint">
    Pick one of the [APIs open to sellers](/sell/apis/index) and deploy an HTTPS endpoint
    that implements its format. The [endpoint contract](/sell/operator-endpoint-contract)
    covers signed requests, the response envelope, and timeouts. The register dialog in
    the dashboard shows the exact schema for the API you pick.
  </Step>
  <Step title="Register it">
    In [Sell APIs > Endpoints](https://getanyapi.com/dashboard/sell/endpoints), enter the
    API it serves, your base URL (HTTPS, port 443, public host), an optional path (default
    `/run`), and your price in USD per 1,000 requests. Through
    `POST /v1/operator/endpoints` you can also send `capacity`, how many requests your
    endpoint takes at once (default 4). You get a **signing secret, shown
    exactly once**. Store it; your endpoint uses it to verify that requests come from
    AnyAPI.
  </Step>
  <Step title="Pass the registration tests">
    Run the registration tests from the endpoint's page, or with
    `POST /v1/operator/endpoints/{id}/suite-runs`, then read the run at
    `GET /v1/operator/endpoints/{id}/suite-runs/{runId}` until it ends. AnyAPI sends your
    endpoint the API's test inputs, signed: a record it finds, an empty list, each not-found
    reason, each input variant the schema allows, and, for an API that pages, the next page through your own cursor.
    Each answer is checked against the API's schema and, where AnyAPI has an answer for that
    input, field by field against it. Your answer to the example input is compared with
    AnyAPI's own answer, fetched while the tests run, and your next page with AnyAPI's next
    page, fetched the same way. Each falls back on its own. If AnyAPI's fetch of the example
    fails or finds nothing, the example is compared with AnyAPI's recorded answer instead. If
    AnyAPI has no next page to compare (its fetch fails, or its first page gave no next page),
    your next page is checked against the API's contract only, and the example keeps its own
    comparison. Every answer must arrive within the API's time
    limit and under 8 MB. A failed test says why and which fields differed; fix your endpoint
    and run the tests again as often as you like. A passing run starts the real-request check.
  </Step>
  <Step title="Pass the real-request check (free the first time)">
    AnyAPI replays real past customer requests for this API to your endpoint, up to 5 at
    once across all of your endpoints being checked, signed and sent exactly like paid requests: you receive the request input, never
    who the customer is. Customers never see your answers and nothing is billed to them. An
    AI reviewer compares each answer with AnyAPI's own answer to the same input and gives a
    verdict:

    | Verdict | Counts as |
    | --- | --- |
    | `clean` | Clean |
    | `sources_differ` | Clean: both answers are right, the sources just differ |
    | `looks_wrong` | A miss |
    | `no_evidence` | Neither way: the reviewer could not tell |
    | `call_failed` | Reliability only: your endpoint failed the call, and failed again when it was retried once a minute later |

    The check measures two things and reports them apart. **Data quality** is the clean
    answers and misses. Where AnyAPI has a second source for the API, an answer that looks
    wrong is checked against it too, and it stays a miss only if both AnyAPI answers agree.
    **Reliability** is how many calls to your endpoint failed. A failed call is never a miss,
    but too many of them fail the check by themselves. A check that did not pass says which of
    the two failed it: `summary.failReason` is `data_quality` or `reliability`, with
    `summary.failReasonText` in plain words.

    The check passes once **at least 95% of answers are clean, at 95% confidence**: 59 clean
    answers with no miss, 93 judged answers with 1 miss, or 124 with 2, within 500 calls.
    There is no minimum number of days and it runs by itself. `summary.progress` estimates the
    time left from your endpoint's own pace so far, or says in plain words why it can't.
    If AnyAPI runs out of past requests for the API, the check uses copies of new customer
    requests as they arrive, which can take longer. If the review is paused on AnyAPI's side,
    the check waits and resumes by itself; that is never a failure of your endpoint. A passed
    endpoint then waits, with no traffic, until you go live.

    Follow it on the endpoint's page or with `GET /v1/operator/endpoints/{id}/trial`.
    `summary` holds the clean answers, misses, calls used, how many more clean answers
    would pass it, and `reliability` (`callsFailed`, `callsAnswered`, and `successNeeded`, how
    many more calls must succeed before the failed ones stop holding a pass back). Each call
    shows the verdict and reason, its notes per field, each compared field with your value and
    AnyAPI's, how your endpoint failed the call if it did, and the request's `X-AnyAPI-Nonce`
    header so you can find it in your own logs.

    **See one call in full.** Open a checked answer on the endpoint's page, or call
    `GET /v1/operator/endpoints/{id}/trial/calls/{trialComparisonId}`: it returns the request
    your endpoint was sent (`input`, never who the customer is), your answer and AnyAPI's.
    `sellerCall` says whether the call was retried (`tries`, `firstTryError`) and, for a failed
    call, what your server answered (`errorBody`, with anything shaped like a credential
    removed). `confirmation` says whether a second AnyAPI source agreed that an answer was
    wrong. Each of the three documents is kept up to 64 KiB.

    **Wait as the API tells you.** Don't poll on a fixed interval. `summary.progress` carries
    `etaMinSeconds`, `etaMaxSeconds`, an `explanation`, and `pollAfterSeconds`; the response
    also sends the same delay as the `Retry-After` header. Both estimates are null when no time
    can be estimated, for example while the check waits for new customer requests. All of your
    endpoints being checked share one limit on calls in flight, so one endpoint's pace changes
    when another of your checks starts or ends.

    **You are told when it ends.** AnyAPI emails your account's address when a check passes or
    fails and when AnyAPI changes an endpoint's status, one email for everything new. The same
    events are at `GET /v1/operator/events`, across all your endpoints: pass `?since=` on the
    first read, then the returned `cursor` as `?after=`.
  </Step>
  <Step title="Read the rundown and fix what it lists">
    When the check ends, pass or fail, the reviewer writes a **data quality rundown**: a
    summary, the top fixes, and for each output field a rating (*fine*, *could be better*,
    or *wrong*), what it saw, what to change, how many answers it affected, and up to 3
    example calls. The endpoint's page shows it, and clicking an example opens that call. Through
    the API it is `summary.rundown` in `GET /v1/operator/endpoints/{id}/trial`; each example is
    a call's nonce, or `input <hash>` for an input with no call left to show.

    If the check did not pass, fix what the rundown lists, worst first, then click **Fix these,
    then run the check again**, or call `POST /v1/operator/endpoints/{id}/trial/restart` and run
    the registration tests again; their pass starts a new check. You can restart while the check
    runs, or in draft after one; a check that already passed can't be restarted. Earlier calls
    stay readable but stop counting.

    **The first check is free. Running it again costs what the previous check cost AnyAPI to
    run** (its own fetches and the AI review), taken from your AnyAPI balance when the new check
    starts. `summary.nextAttemptUsd` shows the amount, and the endpoint's page states it next to
    the button. If your balance can't cover it, the restart answers HTTP 402
    `check_charge_short` with a message naming the amount; top up and try again.

    **If a failure was our fault, the re-run is free.** When AnyAPI finds that a check failed
    because of a mistake on its side, it puts the endpoint back into its check itself. You get
    a `check_rerun` event and email saying so, that check charges nothing
    (`summary.freeRerun` is true), and you don't need to restart anything.
  </Step>
  <Step title="Before you go live: verify your identity">
    Once one of your endpoints passes its check, complete an identity check from the
    **Getting started** checklist in [Sell APIs](https://getanyapi.com/dashboard/sell): a
    government photo ID and a selfie with our verification partner Didit, plus a sanctions
    screening. You get 3 attempts; after that, email
    [support@getanyapi.com](mailto:support@getanyapi.com). AnyAPI keeps only the result,
    your legal name, the country that issued your ID, and the sanctions result. We don't
    store your ID images or selfie.
  </Step>
  <Step title="Before you go live: connect PayPal">
    In [Sell APIs > Earnings](https://getanyapi.com/dashboard/sell/earnings), click
    **Connect PayPal** and sign in with Log in with PayPal. PayPal is how you get paid. The
    account must be verified, in your own name, and in a
    [country PayPal Payouts supports](https://docs.paypal.ai/growth/payouts/reference/countries-supported-features).
    If its name differs from the name on your ID, we show a warning and check it during
    review; it doesn't stop you. If PayPal isn't available to you, email
    [support@getanyapi.com](mailto:support@getanyapi.com) and we'll look at alternatives.
  </Step>
  <Step title="Get approved and go live">
    A person at AnyAPI reviews your check results, your identity check, and your PayPal
    account, then approves your account. Your endpoint then serves real traffic in a
    monitored phase, and fully live while quality holds. You earn from the first request
    you win. If quality drops, the endpoint is paused automatically and re-tested until it
    recovers. You can also pause it yourself, and resume it later, from its page (see
    [Pause and resume an endpoint](#pause-and-resume-an-endpoint)). Withdraw
    your earnings to PayPal from $20; the first payout unlocks 30 days after you become a
    seller, and AnyAPI reviews every payout before it's sent. See
    [Pricing, fees & payouts](/sell/pricing-fees-payouts).
  </Step>
</Steps>

## When AnyAPI's answer looks wrong

If you believe AnyAPI's answer for a registration test or a check call is wrong,
don't copy it. File a data report with
`POST /v1/operator/endpoints/{id}/data-reports`: send `suiteRunId` and `caseId` for a test,
or the call's `trialComparisonId` for a check call, plus a `message` saying what is wrong
(and optionally the `field`). A person at AnyAPI reviews it; filing one doesn't change your
results by itself. `GET` on the same path lists your reports and their status. On the
endpoint's page, open a missed answer and choose **This is wrong** to file the same report;
its status then shows on that call.

## Let your agent manage it: seller keys

Under **Connect your agent** in [Sell APIs](https://getanyapi.com/dashboard/sell), create a
seller key and copy the prompt for your own AI agent. With that key your agent can do what the
seller dashboard does: register endpoints, run the registration tests, read the real-request check's results and
restart it, file data reports, set price and capacity, pause and resume an endpoint, rotate its
signing secret, edit the seller profile, and read earnings, payouts, the identity check status
and whether PayPal is connected. It can also change an endpoint's URL and retire an endpoint,
which only the API offers today.

A seller key can't run APIs as a customer or spend your balance. Four steps stay with a
person in the dashboard: accepting the Seller Terms, starting the identity check, linking
PayPal, and requesting a payout. Your agent never accepts the Seller Terms: while they aren't
accepted, it gives you the link to
[Sell APIs](https://getanyapi.com/dashboard/sell), where you read and accept them, and a seller
key that tries to accept them is refused with that same link. The full seller API, with every
route, its errors, and what a seller key may call, is in
[`getanyapi.com/operator-onboarding/SKILL.md`](https://getanyapi.com/operator-onboarding/SKILL.md).

## Pause and resume an endpoint

To stop an endpoint from receiving customer traffic right away, click **Pause endpoint**
under **Danger zone** on its page and then **Confirm pause**, or call
`POST /v1/operator/endpoints/{id}/pause`. The endpoint keeps its status and check progress,
and `GET /v1/operator/endpoints/{id}` shows `pausedBySeller: true`.

To turn it back on, click **Resume endpoint** on the same page, or call
`POST /v1/operator/endpoints/{id}/resume`. The endpoint picks up where it stopped: same
status, same check progress, and `pausedBySeller` returns to `false`. Resume only undoes
your own pause. A pause AnyAPI made, such as *Paused (quality)* or a pause for false
answers, stays in place.

## Change an endpoint's URL

If you mistyped the URL or moved to a new host, call
`POST /v1/operator/endpoints/{id}/url` with `{"baseUrl": "https://...", "path": "/run"}`.
Leave out `path` to use the default `/run`. The new URL is checked exactly as registration
checks it: HTTPS, port 443, a public host, and no credentials in the URL. A refused URL
answers 400 with the reason.

A new URL means a new endpoint to verify. The endpoint goes back to draft from any status
at once, so it receives no paid requests and no check calls. Earlier test passes and check
calls no longer count. It must pass the registration tests, the real-request check and
AnyAPI's approval again. A suspended account gets 403, and a retired endpoint gets 409.

## Retire an endpoint

To stop selling on an endpoint for good, call `POST /v1/operator/endpoints/{id}/retire`.
No paid request or check call reaches it again, and nothing brings it back. It stays in your
endpoint list with status `retired`, and its earnings stay yours. Retiring it again answers
409. A retired endpoint still counts as your endpoint for that API, so registering the same
API again answers 409.

## What the statuses mean

| Status in the dashboard | What it means |
| --- | --- |
| Draft | Registered but not serving traffic. Run the registration tests when your endpoint is ready. |
| Tests running | AnyAPI is verifying your responses match the API's schema. |
| Check running | Real past customer requests are sent to you, and an AI reviewer compares each answer with AnyAPI's. |
| Check passed | Passed the real-request check; receives no traffic until you have verified your identity, connected PayPal, and AnyAPI has approved your account. |
| Live (monitored) | Serving and earning, with quality watched extra closely. |
| Live | Serving and earning on real customer traffic. |
| Paused (quality) | Paused by the automatic quality checks; re-tested and restored automatically when it passes. |
| Retired | Permanently removed from routing. |
